## 기준 소스

`source/NEXT VERSION/V0.0.3/KrossSync.luau` 작업본을 기준으로 작성한 로컬 준비 문서입니다. [참조 소스](https://github.com/NoName-wks/KrossSync/blob/bf2cd0afe1e8e0503def646c7a71f8addb45f9d3/source/NEXT%20VERSION/V0.0.3/KrossSync.luau)는 커밋 `bf2cd0a`에 고정했습니다. 별도의 v0.0.3 릴리즈 태그를 전제로 하지 않습니다.

## v0.0.2와의 차이

| 항목 | v0.0.2 | v0.0.3 |
| --- | --- | --- |
| 자동 조회 작업 | 한 주기의 모든 키 작업이 끝나야 다음 주기로 진행 | 키별 독립 예약 |
| 자동 조회 예외 | 조회 작업 정리가 중단될 수 있음 | 예외 후 작업 상태 정리와 다음 조회 시도 |
| `UnSync` 영구 저장 | 공유 서버 목록이 비었을 때 시도 | 다른 서버 ID가 남아 있어도 시도 |
| `UnSync` 저장 대상 | 갱신 콜백에서 보관한 값 | MemoryStore 갱신이 확정한 최신 래퍼 |
| 더 최신인 영구 값 | 오래된 공유 값 저장이 거부되면 해제 실패 가능 | 덮어쓰지 않고 해제 성공 처리 |

## 해제와 비용

`UnSync`는 공유 서버 목록에서 현재 JobId를 제거하고 확정된 래퍼의 `data`를 DataStore에 저장합니다. 다른 서버 기록이 남아 있어도 저장하므로, 중단된 서버 기록 때문에 남은 서버의 해제 저장이 생략되던 경로를 보강합니다.

별도 MemoryStore `GetAsync`는 추가하지 않습니다. 일반 해제 경로마다 DataStore `UpdateAsync` 요청이 발생할 수 있으며 동일 스냅샷은 쓰기를 취소할 수 있습니다. 요청 오류에 대한 재시도는 추가 요청을 사용합니다.

영구 저장 실패 시 재시도용 로컬 값을 유지합니다. 더 최신인 영구 버전으로 인해 `SaveData`가 `stale`을 반환하면 기존 값을 보존하고 해제합니다. 모든 서버가 영구 저장 전에 갑자기 종료되는 상황까지 보장하는 변경은 아닙니다.

## 유지되는 계약

- DataStore에는 일반 키의 `data`, MemoryStore와 `LastData`에는 전체 래퍼를 둡니다. 삭제된 영구 키에는 표식이 남습니다.
- `Set`은 영구 저장 후 공유하고 `(dataSaved, memorySaved)`를 반환합니다.
- `SetMemory`는 전체 래퍼를 갱신하며 즉시 영구 저장하지 않습니다. 임시 값은 `memory`에 넣으세요.
- `Save`의 60초 조건은 호출 시 검사합니다. `true`가 영구 저장 완료를 항상 뜻하지 않습니다.
- 자동 조회 간격 15초, 공유 영구 검증 간격 300초, 검증 예약 인계 60초는 유지됩니다. 정확한 복구 시간 보장은 아닙니다.
- `GetData`의 반환 `data`에는 공유 미저장 변경이 보존될 수 있어 특정 요청의 영구 반영 여부를 그 값만으로 확정할 수 없습니다.
- `OnNewData`는 자동 조회가 발견한 최종 상태 변경을 알리며 모든 중간 변경이나 삭제 전용 이벤트를 제공하지 않습니다.

## 검증 기록

다음은 기존 `V0.0.3_TEST_RESULTS.json`과 `V0.0.3_NOTES.md`에 보존된 결과입니다. 이 위키를 작성하면서 재실행하지 않았습니다.

- 모의 저장소·가속 시계 검사 70개 통과: 기존 회귀 62개, 조회 격리·복구 2개, 해제 검사 5개, 충돌 모형 1개.
- 실제 저장소 집중 검사 통과: Studio Edit 세션의 독립 인스턴스에서 최신 공유 값 저장·더 최신인 영구 값 보호를 확인했습니다. 실제 서버 충돌 검사는 아닙니다.
- 2026-10-18 두 라이브 서버의 정상 종료 실행 `V3N_0925634e499e` 통과: 같은 PlaceVersion 1039와 서로 다른 JobId를 사용했습니다.
- 첫 서버의 `close.ready=true`, `close.completed=true`와 두 번째 서버의 `passed=true`, `complete=true`가 기록됐습니다.
- 동시 `Set`, 동시 `SetMemory`, 최신 공유 값의 `UnSync` 저장, 삭제 경쟁, 부하, 주입 오류 재시도와 복구를 확인했습니다.
- 정상 종료 실행의 요청 오류·부하 쓰기 실패 카운터는 양쪽 모두 0회입니다. 커밋 전 MemoryStore 실패를 서버별 4회 주입했습니다.
- 기록된 복구 시간은 예약 인계 71초, 영구 값 294초, 삭제 표식 296초이며 복구 대상 키별 자동 영구 읽기는 1회였습니다. 이 실행의 관측값이며 시간·용량 보장이 아닙니다.

실제 갑작스러운 서버 종료, 실제 서비스 응답 손실, 운영 규모 부하와 장시간 안정성은 아직 미검증입니다. 강제 종료 검증은 새 RunId와 `ExitMode="Abrupt"`의 별도 실행이 필요합니다.

## 적용 시 확인

1. v0.0.3 폴더의 영어·한국어 모듈 중 하나를 선택합니다.
2. 같은 서버의 여러 플레이어가 길드를 공유하면 마지막 사용이 끝난 뒤 키를 해제합니다.
3. 중요한 변경은 즉시 `Set`으로 저장하고, 해제 실패 시 새 쓰기를 멈춘 뒤 재시도합니다.
4. 서로 다른 버전의 혼합 운영은 별도로 검증합니다.
5. 테스트 Script와 `Tests` 폴더는 운영 배포에서 제외합니다. Studio에서 비활성화만 했다면 게시된 플레이스에 반영됐는지도 별도로 확인해야 합니다.
