Service는 require 결과, sync는 Service.get(...)으로 얻은 인스턴스다. get은 점 호출, 나머지 메서드는 콜론 호출이다.

함수 하는 일 반환값
KrossSyncService.get(storeName, dataTemplate, memoryTemplate, expiration?) 저장소별 인스턴스를 만들거나 재사용한다. 기본 만료 시간은 600초다. 같은 이름을 재사용할 때는 같은 템플릿 테이블 참조를 전달해야 한다. 인스턴스. 기존 인스턴스와 템플릿 참조가 다르면 false.
Get(key, force?) MemoryStore부터 읽는다. 없으면 DataStore에서 복구하고, 양쪽에 없으면 템플릿으로 생성한다. 성공 시 현재 서버의 동기화를 시작한다. wrapper 또는 false. 일부 복구·부분 성공·생성 실패 경로에서는 두 번째 값으로 {Data=boolean, Memory=boolean}을 반환한다. 상태 표는 항상 반환되는 값이 아니다.
GetData(key, force?, expectedData?, publishOnly?) DataStore를 캐시 없이 읽고 삭제 상태를 검사한다. 버전을 비교해 MemoryStore와 로컬 wrapper를 복구·조정한다. 임시 memory는 가능한 한 보존한다. 복구된 wrapper. 존재하지 않으면 nil, 오류·삭제·충돌 등으로 처리하지 못하면 false.
GetMemory(key, force?) MemoryStore의 wrapper를 읽고 템플릿 누락 필드를 보충한다. 필요하면 현재 서버를 등록하고 서버 목록을 정리한다. wrapper. 공유 값이 없으면 nil, 오류·삭제·처리 불가이면 false.
Save(key, valueOrCallback, expiration?, force?) 우선 MemoryStore를 갱신한다. 마지막 영구 저장 기준 60초가 지났으면 .data도 저장을 시도한다. 이때 영구 저장만 실패하면 백그라운드 재시도를 예약한다. 성공 여부 boolean. true여도 영구 저장이 완료됐다는 보장은 아니다.
SaveData(key, valueOrCallback, force?) .data만 DataStore에 즉시 저장하고 로컬 wrapper를 갱신한다. MemoryStore에 새 값을 전파하는 함수는 아니다. 오래된 snapshot과 중복 작업을 검사한다. 성공 여부. 일부 거절 경로는 false, "stale" 또는 false, "uncertain".
SaveMemory(key, valueOrCallback, expiration?, force?, preserveDataVersion?, verifiedMissing?, publishOnly?) MemoryStore의 전체 wrapper를 원자적으로 갱신한다. 버전·순서·삭제 표식과 서버 목록을 보호한다. 값이 없으면 영구 상태를 확인한 뒤 복구한다. 성공 여부 boolean. 영구 데이터 쓰기를 직접 수행하지 않는다.
Set(key, valueOrCallback, expiration?, force?) .data를 DataStore에 먼저 저장하고, 확정된 값을 MemoryStore에 반영한다. 메모리 반영만 실패하면 같은 영구 버전의 전파를 백그라운드에서 재시도한다. dataSuccess, memorySuccess. true, false는 영구 저장은 끝났지만 메모리 반영은 아직 실패한 상태다.
SetMemory(key, valueOrCallback, expiration?, force?, verifiedMissing?, publishOnly?) 일반적인 MemoryStore 갱신용 진입점이다. 내부적으로 SaveMemory를 호출한다. .memory뿐 아니라 wrapper의 .data도 바꿀 수 있지만 영구 저장은 하지 않는다. 성공 여부 boolean. 이 함수 자체가 실패한 호출을 별도 작업으로 재전달 예약하지는 않는다.
Remove(key) DataStore에 영구 삭제 표식을 먼저 저장한 뒤 MemoryStore에도 삭제 표식을 기록한다. 영구 삭제 후 메모리 처리만 실패하면 재시도를 예약한다. dataRemoved, memoryRemoved.
RemoveData(key) DataStore에만 영구 삭제 표식을 남기고 현재 서버의 로컬 캐시를 정리한다. MemoryStore의 기존 값을 즉시 지우는 함수는 아니다. 성공 여부 boolean.
RemoveMemory(key) MemoryStore 항목 자체를 제거하고 현재 서버의 관련 로컬 상태를 정리한다. 영구 데이터는 남기므로 이후 조회에서 공유 캐시가 다시 생길 수 있다. 성공 여부 boolean.
UnSync(key) 최신 MemoryStore 갱신 결과에서 현재 서버를 제외하고 .data를 영구 저장한 뒤 로컬 동기화를 해제한다. 다른 서버 ID가 남아 있어도 저장을 시도한다. 완료 여부 boolean. 더 최신인 영구 데이터가 있으면 덮어쓰지 않고 해제한다. 저장 실패 시 재시도용 값을 유지한다. 동기화하지 않은 키는 false.

데이터 구조

  • rawData: 실제 영구 데이터. 예: {coins = 100}.
  • wrapper: data, memory, onlineServers, 시간과 버전 정보가 들어 있는 동기화용 테이블.
  • DataStore에는 wrapper.data만 저장한다. 삭제된 키에는 영구 삭제 표식이 남는다.
  • MemoryStore에는 전체 wrapper를 저장한다. memory는 영구 저장하지 않는다.
  • ?는 생략 가능한 인수다. expiration은 MemoryStore 만료 시간이며 기본값은 인스턴스의 ExpirationTime이다.

입력과 반환값

2개 항목
대상 테이블 입력 callback 입력
Save, SaveMemory, SetMemory 전체 wrapper 최신 공유 wrapper를 받아 변경된 wrapper를 반환한다.
SaveData, Set .data가 들어 있는 wrapper 현재 DataStore의 rawData를 받아 새 rawData를 반환한다. 생성 전이면 입력이 nil일 수 있다.
  • Set(key, {coins=100})처럼 rawData 테이블만 전달하는 형태는 현재 구현에서 허용하지 않는다. wrapper 또는 rawData를 반환하는 callback을 사용한다.
  • callback이 nil을 반환하면 갱신을 취소한다. 삭제는 Remove 계열로 처리한다.
  • callback은 충돌·재시도로 다시 실행될 수 있으므로 지급, 이벤트 발송 등 외부 부작용을 넣지 않는다.
  • Set이 true, false를 반환한 뒤 같은 증가 callback을 무조건 재호출하면 이미 저장한 변경을 중복 적용할 수 있다.
  • force=true는 서비스 상태·Critical 검사 우회다. 키별 잠금, 삭제 표식, 버전 보호까지 우회하지 않는다.
  • expectedData, preserveDataVersion, verifiedMissing, publishOnly는 내부 복구·전파용 인수다. 일반 호출에서는 생략한다. 특히 verifiedMissing은 외부 boolean이 아니라 내부 전용 토큰이다.
  • SaveMemory와 SetMemory는 직접 영구 저장하지 않지만, 공유 값 부재를 검증하려고 DataStore를 읽을 수 있다.
  • SetMemory로 .data를 바꾸면 이후 Save나 UnSync에서 영구 저장될 수 있다. 영구 저장하지 않을 임시 값은 .memory에 넣는다.
  • Remove와 RemoveData는 물리적인 영구 데이터 삭제 대신 삭제 표식을 남긴다. 일반 저장으로 같은 키를 다시 생성하는 기능은 제공하지 않는다.

자동 조회 스케줄러 키별 15초 간격을 유지한다. 한 키의 지연·예외가 다른 키를 막지 않도록 작업 상태를 분리한다.
OnError 연결 처리 최근 오류를 저장소별로 기록한다. 30초 내 오류가 기준 횟수에 도달하면 Critical·Error 상태로 전환하고 복구 감시를 시작한다.
초기 접근 상태 검사 작업 저장소 접근 가능 여부를 확인하고 서비스 접근 상태를 초기화한다.
UpdateAsync 변환 처리 각 API의 데이터·버전·삭제 표식 갱신을 수행한다. 충돌 시 여러 번 호출될 수 있다.
예약·재시도 작업 삭제 기록 만료 정리, 영구 저장, 메모리 전파, 공유 삭제 표식 재시도를 수행한다.

Signal

5개 Signal

Signal은 일반 함수가 아니며 :Connect(callback)으로 구독한다.

Signal 발생 조건과 인수
sync.OnNewData 자동 조회에서 .data 또는 .memory 변경을 감지했을 때 전체 wrapper를 전달한다. 키를 별도 인수로 전달하지 않는다.
sync.OnGettingToggle 키별 읽기 잠금이 변경됐을 때 읽기 중 여부를 전달한다. 키를 별도 인수로 전달하지 않는다.
sync.OnSavingToggle 키별 쓰기 잠금이 변경됐을 때 쓰기 중 여부를 전달한다. 키를 별도 인수로 전달하지 않는다.
Service.OnCriticalToggle Critical 변경 시 전체 Critical 여부와 상세 상태 테이블을 전달한다.
Service.OnError 요청 처리 실패 시 위치, 오류, 저장소 이름, 키, 입력값을 전달한다. 위치 1은 DataStore, 2는 MemoryStore다. 입력값은 생략될 수 있다.

운영 주의

  • MaxRetryTime은 초가 아니라 시도 횟수다. 기본값은 5회이며 nil은 무제한 시도다.
  • 중요한 영구 변경에는 Set을 사용하고 첫 번째 반환값을 확인한다. Save(true)나 SetMemory(true)만으로 영구 저장 완료를 판단하지 않는다.
  • 백그라운드 재시도와 종료 정리는 서버가 살아 있는 동안만 수행할 수 있다.
  • 실제 두 서버의 정상 종료·복구는 검증됐지만, 실제 갑작스러운 서버 종료 검증은 아직 남아 있다.
