# V0.1.0 Alpha

V0.0.4 기반 작업본이며, 이전 버전과 호환되지 않습니다. MessagingService는 포함하지 않습니다.

DataStore 메타데이터는 `__ksRev`, `__ksOp`, `__ksSrcRev`, `__ksSrcSeq`만 사용합니다. 이전 키는 읽거나 변환하지 않습니다. 기존 버전과 같은 저장소를 혼용하지 마세요.

## 키별 작업 순서

- 같은 키의 Save, Set, Remove를 직렬화합니다. 다른 키는 독립적으로 진행합니다.
- 이미 시작한 저장소 작업은 끊지 않습니다. 대기 중인 Remove가 다음 순서에서 우선합니다.
- Save와 Set은 종류에 관계없이 접수 순서대로 적용합니다. 호환되는 연속 함수는 합칩니다.
- Save(1) 실행 중 Save(2), Set(3)이 대기하면 1 이후 2를 MemoryStore에 반영하고, 그 data에 3을 적용해 DataStore에 한 번 저장합니다. 최종 결과는 3(2(1(old)))입니다. Set의 최종 값은 영구 저장 후 공유합니다.
- expiration 또는 force가 다르거나 테이블 입력이면 별도 작업으로 처리합니다. 대기열은 서버 인스턴스 로컬이며, 서버 간에는 기존 버전 검사와 삭제 표식 보호를 유지합니다.
- Get과 직접 저장소 메서드는 대기열에 들어가지 않습니다. 키 작업자가 바쁘면 기존처럼 실패합니다.

## 대기와 실패 반환

- 인스턴스의 WaitForWorkResult 기본값은 true입니다. Save/Set의 다섯 번째 인자, Remove의 두 번째 인자로 true/false를 넘기면 기본값을 덮어씁니다. nil은 기본값을 사용합니다.
- 기다리는 모드는 기존 성공 반환을 유지합니다. 즉시 모드는 접수 객체를 반환하고, receipt:Await()로 같은 결과를 받습니다.
- 최종 실패 시 Save는 false, remainingFunc, reason을, Set/Remove는 false, false, remainingFunc, reason을 반환할 수 있습니다.
- 미반영이 확인된 배치는 기존 요청 재시도 후 한 번 더 대기열에서 처리합니다. 실패 함수와 새 함수는 접수 순서대로 합칩니다.
- 합쳐진 함수는 배치 전체에 하나입니다. Save 또는 혼합 배치는 전체 래퍼를, Set만 있는 배치는 raw data를 입력으로 받습니다. 이미 반영된 부분은 포함하지 않습니다. 같은 배치를 여러 번 다시 실행하지 마세요.
- 커밋 여부가 불확실하면 remainingFunc 없이 uncertain을 반환합니다. DataStore만 성공한 Set은 true, false를 반환하며, 후속 Save는 확정 값을 공유 캐시에 반영하기 전에는 실행하지 않습니다.
- 삭제 표식이 확정되면 대기 쓰기를 취소합니다. 삭제 미반영이 확인되면 이어서 처리하고, 확인할 수 없으면 대기 요청을 uncertain으로 종료합니다.
- 종료 시 새 요청은 거부하고 기존 작업을 기존 종료 제한 내에서 정리합니다. 대기열은 영구 저장소가 아닙니다.
